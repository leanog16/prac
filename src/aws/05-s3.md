## Buckets and objects

**Amazon S3** stores **objects** (files up to 5 TB, plus metadata) in **buckets**.

- Bucket names are **globally unique** across all AWS accounts, DNS-compatible (lowercase, digits, hyphens), and a bucket lives in one region.
- An object is addressed by its **key**: `invoices/2026/11/inv-1042.pdf`. There are no real folders; `invoices/2026/` is just a **prefix**, which the console displays as folders.
- S3 is **strongly consistent**: after a successful PUT, every subsequent read sees the new object.
- Designed for 99.999999999% (11 nines) durability by storing data across multiple AZs.

## The CLI

```bash
aws s3 mb s3://acme-invoices-prod --region eu-west-1           # make bucket
aws s3 cp report.pdf s3://acme-invoices-prod/reports/          # upload
aws s3 cp s3://acme-invoices-prod/reports/report.pdf .         # download
aws s3 ls s3://acme-invoices-prod/reports/ --recursive --human-readable
aws s3 sync ./dist s3://acme-site --delete                     # mirror a folder, removing extras
aws s3 rm s3://acme-invoices-prod/tmp/ --recursive
aws s3 presign s3://acme-invoices-prod/reports/report.pdf --expires-in 900
```

`aws s3` is the high-level, file-oriented CLI. `aws s3api` exposes every API operation (`put-bucket-versioning`, `put-bucket-policy`, `get-object-attributes`…).

## Keeping buckets private

**Block Public Access** (on by default for new buckets, and settable for the whole account) overrides any policy or ACL that would make data public. Leave it on unless the bucket truly serves public content, and even then prefer CloudFront in front of a private bucket.

Object ACLs are legacy: new buckets have **Object Ownership = Bucket owner enforced**, which disables ACLs. Control access with IAM policies and **bucket policies**:

```json title=bucket policy: HTTPS only
{
  "Version": "2012-10-17",
  "Statement": [{
    "Sid": "DenyInsecureTransport",
    "Effect": "Deny",
    "Principal": "*",
    "Action": "s3:*",
    "Resource": ["arn:aws:s3:::acme-invoices-prod", "arn:aws:s3:::acme-invoices-prod/*"],
    "Condition": { "Bool": { "aws:SecureTransport": "false" } }
  }]
}
```

Bucket policies also grant **cross-account** access (`"Principal": {"AWS": "arn:aws:iam::222222222222:role/reader"}`); within one account, an IAM policy on the role is enough.

## Encryption

- All new objects are encrypted at rest by default with **SSE-S3** (keys managed by S3).
- **SSE-KMS** uses a KMS key you control: key policies decide who can decrypt, and every use is logged in CloudTrail. Readers then need `kms:Decrypt` as well as `s3:GetObject`. Enable **S3 Bucket Keys** to cut KMS request costs.
- In transit: enforce HTTPS with the policy above.

## Versioning and lifecycle

**Versioning** keeps every version of every object. Overwrites create a new version, and deletes add a **delete marker** instead of destroying data, so accidental deletions and ransomware-style overwrites are recoverable.

```bash
aws s3api put-bucket-versioning --bucket acme-invoices-prod \
  --versioning-configuration Status=Enabled
```

**Lifecycle rules** move or expire objects automatically:

```json title=lifecycle.json
{
  "Rules": [{
    "ID": "archive-then-expire",
    "Status": "Enabled",
    "Filter": { "Prefix": "logs/" },
    "Transitions": [
      { "Days": 30, "StorageClass": "STANDARD_IA" },
      { "Days": 90, "StorageClass": "GLACIER" }
    ],
    "Expiration": { "Days": 365 },
    "NoncurrentVersionExpiration": { "NoncurrentDays": 30 },
    "AbortIncompleteMultipartUpload": { "DaysAfterInitiation": 7 }
  }]
}
```

```bash
aws s3api put-bucket-lifecycle-configuration --bucket acme-invoices-prod \
  --lifecycle-configuration file://lifecycle.json
```

With versioning on, also expire **noncurrent** versions, or old versions pile up and you pay for them forever.

## Storage classes

| Class | For | Notes |
|---|---|---|
| **Standard** | frequently accessed data | the default |
| **Intelligent-Tiering** | unknown or changing access patterns | moves objects between tiers automatically, small monitoring fee |
| **Standard-IA** / **One Zone-IA** | infrequent access, fast retrieval | per-GB retrieval fee, 30-day minimum |
| **Glacier Instant Retrieval** | archives read a few times a year, in milliseconds | 90-day minimum |
| **Glacier Flexible Retrieval** | archives, minutes to hours to restore | |
| **Glacier Deep Archive** | compliance archives, hours to restore | cheapest, 180-day minimum |

## Presigned URLs

Your API shouldn't stream large uploads and downloads through itself. Instead, it hands the client a **presigned URL**: a time-limited URL signed with the API's credentials, which lets the client talk to S3 directly for one specific object and operation.

```python
import boto3

s3 = boto3.client("s3")

download_url = s3.generate_presigned_url(
    "get_object",
    Params={"Bucket": "acme-invoices-prod", "Key": "reports/q3.pdf"},
    ExpiresIn=900,                                   # 15 minutes
)

upload_url = s3.generate_presigned_url(
    "put_object",
    Params={"Bucket": "acme-uploads", "Key": f"avatars/{user_id}.png", "ContentType": "image/png"},
    ExpiresIn=300,
)
```

The URL carries the signer's permissions, so the signing role needs `s3:GetObject` / `s3:PutObject` on that key. Generate keys server-side (never trust a client-chosen key), and keep expirations short.

## Event notifications

S3 can trigger processing when objects arrive: `s3:ObjectCreated:*` on prefix `uploads/` → a Lambda function, an SQS queue, an SNS topic, or EventBridge. The classic example is generating thumbnails for uploaded images. Watch out for loops: a function that writes its output back into the same prefix triggers itself forever.

## Static websites with CloudFront

The production pattern for a single-page app or static site:

1. A **private** S3 bucket with the built files (`aws s3 sync ./dist s3://acme-site --delete`).
2. A **CloudFront** distribution in front of it, using **Origin Access Control (OAC)**: the bucket policy allows only that distribution to read.
3. An **ACM certificate** (in `us-east-1` for CloudFront) and a Route 53 alias record for `www.example.com`.
4. On each deploy, invalidate changed paths: `aws cloudfront create-invalidation --distribution-id E123 --paths "/index.html"`. Give hashed asset files (`app.3f2c1a.js`) long cache lifetimes and `index.html` a short one.

S3's own "static website hosting" endpoint is HTTP-only and requires a public bucket, so CloudFront + OAC is the better choice.

:::quiz
q: What is `reports/2026/q3.pdf` in S3?
- a file in a folder named 2026
+ an object whose key contains slashes; "folders" are just prefixes
- a bucket path
- an invalid key
why: S3 has a flat namespace; the console shows prefixes as folders.
:::

:::quiz
q: Versioning is enabled and someone runs `aws s3 rm` on an object. What happens?
- the object is permanently deleted
+ a delete marker is added; previous versions remain recoverable
- the command fails
- the object moves to Glacier
why: Deletes in a versioned bucket hide the object behind a marker.
:::

:::quiz
q: Objects are encrypted with SSE-KMS. A role has `s3:GetObject` but downloads fail with AccessDenied. What's missing?
+ `kms:Decrypt` on the KMS key
- `s3:ListBucket`
- a public bucket policy
- versioning
why: Reading SSE-KMS objects requires permission to use the key.
:::

:::quiz
q: Why use presigned URLs for user uploads?
+ clients upload directly to S3 for one key and a limited time, without your API proxying the bytes or the client getting AWS credentials
- they make objects public
- they're required for files over 5 GB
- they skip encryption
why: They offload transfer to S3 while keeping access narrowly scoped.
:::
