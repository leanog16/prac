> [!project] Taskboard, step 8: tasks that survive a restart
> Every restart currently wipes the board, because tasks live in a Python dict. This step moves them into a real database with SQLModel: a `Task` table, a session dependency, and endpoints that query instead of loop.

## The pieces

**SQLModel** builds on **SQLAlchemy** (the ORM that talks to the database) and **Pydantic** (validation), so one class can describe both a table and an API schema. Everything here maps directly onto plain SQLAlchemy too.

| Piece | Role |
|---|---|
| **engine** | a connection pool for one database URL |
| **Session** | a unit of work: queries and changes, committed together |
| **table model** (`table=True`) | a class mapped to a table |
| **schemas** (no `table=True`) | request and response shapes |
| **`get_session` dependency** | one session per request, closed afterwards |

## Models: one table, several schemas

```python title=models.py
from sqlmodel import Field, SQLModel


class ProductBase(SQLModel):
    name: str = Field(index=True)
    price: float = Field(gt=0)
    stock: int = 0


class Product(ProductBase, table=True):
    id: int | None = Field(default=None, primary_key=True)
    supplier_note: str | None = None      # internal, never returned


class ProductCreate(ProductBase):
    pass


class ProductRead(ProductBase):
    id: int


class ProductUpdate(SQLModel):
    name: str | None = None
    price: float | None = None
    stock: int | None = None
```

`id` starts as `None` and the database fills it in on insert. `ProductRead` is the response model, so `supplier_note` never leaves the server.

## Engine, tables and the session dependency

```python title=database.py
from typing import Annotated
from fastapi import Depends
from sqlmodel import Session, SQLModel, create_engine

engine = create_engine("sqlite:///shop.db", connect_args={"check_same_thread": False})


def create_tables():
    SQLModel.metadata.create_all(engine)


def get_session():
    with Session(engine) as session:
        yield session


SessionDep = Annotated[Session, Depends(get_session)]
```

For PostgreSQL the URL looks like `postgresql+psycopg://user:password@db:5432/shop`, and it should come from an environment variable, never from source code.

## CRUD

```python title=main.py
from fastapi import FastAPI, HTTPException
from sqlmodel import select

app = FastAPI()


@app.post("/products", response_model=ProductRead, status_code=201)
def create_product(data: ProductCreate, session: SessionDep):
    product = Product.model_validate(data)
    session.add(product)
    session.commit()
    session.refresh(product)              # load the generated id
    return product


@app.get("/products", response_model=list[ProductRead])
def list_products(session: SessionDep, offset: int = 0, limit: int = 50):
    return session.exec(select(Product).offset(offset).limit(limit)).all()


@app.get("/products/{product_id}", response_model=ProductRead)
def read_product(product_id: int, session: SessionDep):
    product = session.get(Product, product_id)
    if product is None:
        raise HTTPException(status_code=404, detail="Product not found")
    return product


@app.patch("/products/{product_id}", response_model=ProductRead)
def update_product(product_id: int, data: ProductUpdate, session: SessionDep):
    product = session.get(Product, product_id)
    if product is None:
        raise HTTPException(status_code=404, detail="Product not found")
    product.sqlmodel_update(data.model_dump(exclude_unset=True))
    session.add(product)
    session.commit()
    session.refresh(product)
    return product


@app.delete("/products/{product_id}", status_code=204)
def delete_product(product_id: int, session: SessionDep):
    product = session.get(Product, product_id)
    if product is None:
        raise HTTPException(status_code=404, detail="Product not found")
    session.delete(product)
    session.commit()
```

| Operation | Call |
|---|---|
| by primary key | `session.get(Product, 5)` → object or `None` |
| query | `session.exec(select(Product).where(Product.price < 20)).all()` |
| first match | `.first()` instead of `.all()` |
| ordering | `select(Product).order_by(Product.price.desc())` |
| insert/update | `session.add(obj)` then `session.commit()` |
| delete | `session.delete(obj)` then `session.commit()` |

> [!warn] Nothing is saved until commit
> `add()` only stages the change. Forgetting `commit()` is the classic "my POST returned 201 but the row isn't there" bug. `refresh()` reloads database-generated values like the id.

## Migrations

`create_all` creates missing tables but never alters existing ones. Real projects manage schema changes with **Alembic** migrations: `alembic revision --autogenerate -m "add stock"`, then `alembic upgrade head`.

## Worked example: the same endpoint, before and after

Before (in memory):

```python
@router.get("/{task_id}")
def get_task(task_id: int):
    task = TASKS.get(task_id)
    if task is None:
        raise HTTPException(404, "Task not found")
    return task
```

After (database):

```python
@router.get("/{task_id}", response_model=TaskOut)
def get_task(task_id: int, session: SessionDep):
    task = session.get(Task, task_id)
    if task is None:
        raise HTTPException(404, "Task not found")
    return task
```

The shape is identical: the **session** replaced the dict. That's the payoff of keeping endpoints thin.

The pieces, end to end:

```python title=db.py
from typing import Annotated
from fastapi import Depends
from sqlmodel import Field, Session, SQLModel, create_engine

class Task(SQLModel, table=True):
    id: int | None = Field(default=None, primary_key=True)   # None until the DB assigns it
    title: str = Field(index=True, max_length=120)
    description: str = ""
    priority: int = 3
    status: str = Field(default="todo", index=True)
    owner: str

engine = create_engine("sqlite:///taskboard.db", connect_args={"check_same_thread": False})

def get_session():
    with Session(engine) as session:
        yield session

SessionDep = Annotated[Session, Depends(get_session)]
```

Creating a task follows a fixed rhythm: **add → commit → refresh**:

```python
@router.post("", response_model=TaskOut, status_code=201)
def create_task(data: TaskCreate, session: SessionDep, user: CurrentUser):
    task = Task(**data.model_dump(), owner=user["name"])
    session.add(task)          # stage the INSERT
    session.commit()           # write it; the DB assigns the id
    session.refresh(task)      # reload so task.id is filled in
    return task
```

> [!plain] In plain English
> The **engine** knows how to reach the database. A **session** is one conversation with it: you stage changes, `commit` makes them permanent, and closing the session ends the conversation. One session per request.

## Querying with select

```python
from sqlmodel import select

stmt = select(Task).where(Task.status == "todo").order_by(Task.priority).offset(0).limit(20)
tasks = session.exec(stmt).all()
```

This is the SQL track's `SELECT … WHERE … ORDER BY … LIMIT … OFFSET`, written in Python. Turn on `create_engine(..., echo=True)` while learning to see the SQL it generates.

## Common mistakes

> [!mistake] Creating tables in production with create_all
> `SQLModel.metadata.create_all(engine)` is fine for demos and tests, but it never **alters** existing tables. Real projects use Alembic migrations.

> [!mistake] Forgetting commit
> Without `session.commit()`, your changes vanish when the session closes, and the API happily returns a task that was never saved.

:::quiz
q: What does `session.refresh(product)` after commit typically give you?
+ values generated by the database, such as the new id
- a new database connection
- the previous version of the row
- nothing; it's required syntax
why: refresh reloads the object's state from the database.
:::

:::quiz
q: A route calls `session.add(obj)` but never `commit()`. What happens?
- the row is saved at the end of the request automatically
+ the change is discarded when the session closes
- an exception is raised
- the row is saved on the next request
why: Changes are part of a transaction that must be committed.
:::

:::quiz
q: Why have `Product` (table) and `ProductRead` (schema) separately?
- SQLModel requires it
+ to control what's stored vs what's exposed, e.g. hiding internal columns
- for speed
- to support SQLite
why: Separate schemas decouple your API contract from your storage.
:::

:::quiz
q: Which returns `None` instead of raising when the row doesn't exist?
+ session.get(Product, 99)
- session.exec(select(Product)).one()
- Product(id=99)
- session.delete(99)
why: get by primary key returns None for a missing row; .one() raises.
:::
